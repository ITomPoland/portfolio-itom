# 🧭 作品集内容定制指南（customize/）

> 这个文件夹是**内容定制知识库**：它不包含任何运行代码，只回答四个问题——
> **「哪里是什么」** → `01-内容地图.md`
> **「该去改哪里、怎么改」** → `02-替换指南.md`
> **「我改过什么、还剩什么占位」** → `03-已修改文件清单.md`
> **「用到的图片在哪个文件夹、属于哪个区域」** → `assets-index.md` + `../public/assets/`

本项目是一个用 **React 19 + Vite 7 + Three.js（R3F）+ GSAP** 构建的 3D 交互作品集：用户走进一条手绘质感走廊，推开四扇门分别进入「关于我 / 作品集 / 创作室 / 联系」四个房间。**替换内容只需要改数据文件、文案和图片，不需要动 3D 渲染逻辑。**

## 📁 文件夹说明

| 文件 | 作用 | 什么时候看 |
| --- | --- | --- |
| `README.md`（本文件） | 入口：用途、目录说明、快速开始 | 第一次拿到项目 |
| `01-内容地图.md` | 全站内容地图：每个房间/板块 → 对应文件 → 控制的字段 → 关联图片 | 想知道"某句话/某张图在哪个文件" |
| `02-替换指南.md` | 逐文件替换手册：字段含义、图片规格与命名规则、残留占位清单、注意事项 | 准备动手改内容 |
| `03-已修改文件清单.md` | 吴桐本地化已改动文件清单（基于 git 状态），标注已改 / 仍为占位 | 核对现状、制作 skill 时参照 |
| `assets-index.md` | 资产索引：`public/assets/<区域>/` 下每个文件的用途与引用代码位置 | 想知道某张图属于哪个区域、被谁引用 |

> **资产实体目录**：所有已使用/生成的图片按区域存放在 **`../public/assets/`**（`about/`、`corridor/`、`gallery/`、`studio/`、`contact/`、`global/`、`placeholders/`），代码通过 `/assets/...` 引用。原文件仍保留在 `public/textures/`、`public/images/` 未删除。

> **路径说明**：三份子文档中的文件路径均以本项目根目录（`portfolio-itom/`）为基准。若你的编辑器里当前目录是 `portfolio-itom/customize/`，请把路径前的 `src/` 理解为 `../src/`。

## 🚀 快速开始

```bash
# 进入项目目录
cd portfolio-itom

# 安装依赖（首次）
npm install

# 启动开发服务器（浏览器打开 http://localhost:5173）
npm run dev
```

生产构建与预览：

```bash
npm run build     # 产物输出到 dist/
npm run preview   # 本地预览构建产物
```

## 🔁 如何按文档逐项替换

1. **先通读 `01-内容地图.md`**，搞清楚整个站点有哪些内容点，各自住在哪个文件。
2. **再打开 `02-替换指南.md`**，从你关心的板块（例如「作品集卡片」）开始逐项替换。每个替换点都给出了：
   - 文件路径 + 需要改的字段
   - 图片规格与命名规则
   - 常见坑（例如普通图与 `_painted` 悬停版要成对替换）
3. **替换完对照 `03-已修改文件清单.md` 的「残留占位」清单扫一遍**，确认没有漏掉 `example.com` 链接、占位图或「吴桐」相关文案。
4. 保存后刷新浏览器验证（大部分改动是热更新，改了 `src/data/*` 或 `public/` 图片需刷新页面）。

**通用替换套路（90% 的内容改动都属于这一类）**：

- 改**文字** → 去对应数据文件或组件里搜中文/英文文案，直接替换。
- 改**图片** → 找到图片在 `../public/assets/<区域>/` 下的文件路径 → 用同名同规格的新图覆盖 → 刷新（注意 `_painted` 双版本，详见 `02-替换指南.md` 注意事项；不确定属于哪个区域先查 `assets-index.md`）。
- 改**链接** → 去数据文件的 `url` / `href` 字段替换。
- 换**人名 / 整个站点身份** → 全项目搜索 `吴桐` 与 `example.com` 批量替换（清单见 `02-替换指南.md` 第 6 节）。

## ⚠️ 三条铁律

1. **只改 `src/data/`、`public/` 与文案；不要动 3D 逻辑文件**（如 `InfiniteSkyManager.jsx` 里的几何/动画代码），除非你清楚自己在做什么。
2. **图片必须保持原有文件名与尺寸**（普通版 + `_painted` 版成对存在），否则会出现加载失败或悬停异常。
3. **`customize/` 文件夹本身只放文档**，不要把项目运行文件复制进来，避免产生"副本漂移"。

## 🧩 这个文件夹与 skill 的关系

如果你要把本项目做成一个「一键换成自己的内容」的 skill，推荐流程：

1. 以本文件夹为知识库（README + 四份子文档）。
2. skill 指令 = 「读取 `customize/` 下的文档 → 按 `02-替换指南.md` 逐项询问/替换 → 对照 `03-已修改文件清单.md` 收尾；需要换图时按 `assets-index.md` 定位 `public/assets/<区域>/` 下的文件」。
3. 可让 skill 先跑一遍「占位扫描」：全项目搜 `example.com`、`吴桐`、`hello@example`，把结果当成待办清单。
